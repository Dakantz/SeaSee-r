# Stream Pointcloud Binary (`/pointclouds/stream-binary`)

## Overview
The `/pointclouds/stream-binary` endpoint provides high-performance binary streaming of 3D point cloud data directly from PostgreSQL / PostGIS (`pgPointCloud`) storage to frontend WebGL visualizers (such as Three.js).

Instead of transferring bloated JSON structures or generating intermediate `.ply` files on disk, this endpoint streams raw point attribute buffers asynchronously using dynamic field filtering (`field__operator=value`). This minimizes network overhead, eliminates server-side disk I/O bottlenecks, and allows frontend clients to directly map incoming 16-byte binary buffers into WebGL vertex attribute buffers (`BufferGeometry`).

---

## Endpoint Specification

- **HTTP Method**: `GET`
- **Path**: `/pointclouds/stream-binary`
- **Response Content-Type**: `application/octet-stream`
- **Headers**:
  - `Content-Disposition`: `attachment; filename="pointcloud_lod{lod}.bin"`

### Parameters

| Parameter | Type | Location | Required | Default | Description |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `lod` | `integer` | Query | Yes | — | Level of Detail (LOD) pyramid level to stream (`0` represents full resolution / base LOD; selectable from `0` to `10`). |
| Dynamic Filters | `string` / `number` | Query | No | — | Dynamic filter parameters formatted as `field__operator=value` (or `field=value` for equality). Parsed by `QueryFilterParser`. |

#### Supported Filter Fields & Operators

- **Allowed Fields**: `pointcloud_id` (or `id`), `number_of_points`, `created_at`, `orig_filename`, `min_x`, `max_x`, `min_y`, `max_y`, `min_z`, `max_z`, `video_start_at`, `video_stop_at`.
- **Supported Operators**: `eq` (`=`), `ne` (`!=`), `gt` (`>`), `gte` (`>=`), `lt` (`<`), `lte` (`<=`), `like` (`LIKE`), `in` (`IN`).
- **Examples**:
  - `GET /pointclouds/stream-binary?lod=0&pointcloud_id=e360394b-a241-49e5-bb66-97fee8bd85ef`
  - `GET /pointclouds/stream-binary?lod=2&number_of_points__gte=50000`
  - `GET /pointclouds/stream-binary?lod=0&pointcloud_id__in=uuid1,uuid2`

## Stream Pointcloud Summary (`/pointclouds/stream-summary`)

The `/pointclouds/stream-summary` endpoint (also mounted at `/stream-summary`) accepts the same `lod` and dynamic parameter filters (`field__operator=value`) as `/pointclouds/stream-binary`. Instead of streaming binary vertex buffers, it returns a JSON summary containing the total point count, spatial 3D bounding box, bounding box center, connected pointcloud metadata, and connected camera headers selected by the query filters.

### Endpoint Specification

- **HTTP Method**: `GET`
- **Paths**: `/pointclouds/stream-summary`, `/stream-summary`
- **Response Content-Type**: `application/json`

### Query Logic

To optimize performance and avoid memory overhead, the summary query transforms point selection criteria into patch-level aggregation queries. It computes point counts and spatial bounding boxes directly using PostGIS `pgPointCloud` patch header aggregate functions (`SUM(PC_NumPoints(patch))`, `PC_PatchMin`, and `PC_PatchMax`), combined with SQL join filters generated by `PointCloudQueryBuilder`:

```sql
-- Parameterized stream-summary query generated by PointCloudQueryBuilder:
SELECT 
    COALESCE(SUM(PC_NumPoints(p.patch)), 0) AS total_points,
    MIN(PC_PatchMin(p.patch, 'X')) AS min_x,
    MIN(PC_PatchMin(p.patch, 'Y')) AS min_y,
    MIN(PC_PatchMin(p.patch, 'Z')) AS min_z,
    MAX(PC_PatchMax(p.patch, 'X')) AS max_x,
    MAX(PC_PatchMax(p.patch, 'Y')) AS max_y,
    MAX(PC_PatchMax(p.patch, 'Z')) AS max_z
FROM pointcloud_patches_lod0 p
JOIN pointcloud_metadata pm ON p.pointcloud_id = pm.id
-- LEFT JOIN video_metadata vm ON pm.video_metadata_id = vm.id (if filtering on video timestamps)
WHERE pm.id = :p_0;
```

A secondary query (`SELECT DISTINCT p.pointcloud_id ...`) fetches distinct foreign key IDs to return all connected `PointCloudMetadata` objects and associated `CameraHeader` records matching the filter criteria.

## Binary Data Layout & Protocol

Each point (vertex) in the binary stream is packed sequentially using a 16-byte aligned struct:

| Field | Data Type | Byte Offset | Size (Bytes) | Endianness | Description |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `X` | `Float32` (`<f4`) | 0 | 4 | Little-endian | Spatial X coordinate |
| `Y` | `Float32` (`<f4`) | 4 | 4 | Little-endian | Spatial Y coordinate |
| `Z` | `Float32` (`<f4`) | 8 | 4 | Little-endian | Spatial Z coordinate |
| `R` | `Uint8` (`u1`) | 12 | 1 | — | Red color channel (`0-255`) |
| `G` | `Uint8` (`u1`) | 13 | 1 | — | Green color channel (`0-255`) |
| `B` | `Uint8` (`u1`) | 14 | 1 | — | Blue color channel (`0-255`) |
| `A / Pad` | `Uint8` (`u1`) | 15 | 1 | — | Alpha / Alignment Padding (`255`) |

### NumPy DType Definition

```python
VERTEX_DTYPE = np.dtype([
    ('x', '<f4'),
    ('y', '<f4'),
    ('z', '<f4'),
    ('r', 'u1'),
    ('g', 'u1'),
    ('b', 'u1'),
    ('a', 'u1')
])
```

- **Total Vertex Stride**: `16 bytes per point`.
- **Chunked Transfer Encoding**: Data is yielded asynchronously in chunk buffers of `524,288 bytes` (512 KB, ~32,768 vertices per chunk) via FastAPI `StreamingResponse`.

## Response & Error Handling

- **`200 OK`**: Successfully returns an octet-stream chunked payload of 16-byte vertex records or summary JSON.
- **`400 Bad Request`**: Returned if filter fields or operators are invalid/unauthorized, or parameter parsing fails (e.g., invalid UUID format or unknown field name).
- **`404 Not Found`**: Returned if no point cloud metadata record exists matching the provided query filters.
- **`500 Internal Server Error`**: Database streaming or query failure.
